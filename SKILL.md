# line-chrome

Wraps the **official LINE Chrome extension** (`chrome-extension://ophjlpahpchlmihnnnihgmmeilfjmjjc/`)
instead of touching the LINE Mac app or LINE's private API.

**Why this design:**
- Uses Chrome's standard JS execution surface (AppleScript → `tell ... execute javascript`).
- All outbound traffic is generated by the user's own logged-in LINE extension — same as typing in the UI.
- No token harvesting, no Thrift reverse-engineering, no grey-area custom client.

Run commands as `python3 cli.py <subcommand>` from this skill directory. macOS only.

## Prerequisites

1. Install the official LINE Chrome extension from <https://chromewebstore.google.com/detail/line/ophjlpahpchlmihnnnihgmmeilfjmjjc>.
2. Click the extension icon, log in via QR (once). Never automate the QR flow.
3. Detach the extension to its own window — AppleScript can only inject JS into Chrome tabs, not extension popups.
4. Enable Chrome's `View → Developer → Allow JavaScript from Apple Events`.
   `python3 cli.py enable-applescript` automates this (needs Accessibility permission).

## Usage

```
python3 cli.py status                    # Chrome attach OK? selectors loaded?
python3 cli.py enable-applescript         # turn on AppleScript JS execution if off
python3 cli.py diagnose                   # check each selector against the live DOM
python3 cli.py list-rooms
python3 cli.py list-contacts
python3 cli.py send --to "홍길동" --text "안녕"
python3 cli.py history --room "Family" --limit 50
python3 cli.py search --room "Family" --query "회의"
python3 cli.py watch --interval 5         # poll for new messages
python3 cli.py selectors show
python3 cli.py selectors set message_input "textarea-ex.text"
python3 cli.py cache-info                 # locate the extension's LevelDB store
python3 cli.py cache-dump --out ~/line-cache-copy
```

All commands print JSON to stdout.

## Fixing broken selectors

When LINE updates the extension and a selector breaks, no code change is needed:

1. Run `python3 cli.py diagnose` → tells you which selector key fails.
2. Open Chrome DevTools inside the LINE extension window, inspect the element.
3. Pick a stable selector (prefer `data-*` / `aria-*` / `role` > class > tag).
4. Override it, in priority order:
   - **CLI flag (one-off):** `--selector message_input='…'` (repeatable on any command).
   - **User override file (persistent):** `~/.config/line-chrome/selectors.json`
     ```json
     { "selectors": { "message_input": "textarea-ex.text" } }
     ```
   - **Repo default:** `selectors.json` in this directory.
5. Re-run `diagnose` to confirm.

Selector priority: `--selector` > `~/.config/line-chrome/selectors.json` > repo `selectors.json`.

## Path 2 — LevelDB cache (read-only)

`history` / `search` only see messages currently rendered in the DOM. The extension's
full IndexedDB store lives at
`~/Library/Application Support/Google/Chrome/<profile>/IndexedDB/chrome-extension_ophjlpahpchlmihnnnihgmmeilfjmjjc_0.indexeddb.leveldb/`.

- `cache-info` — locate it, show size and last-modified time.
- `cache-dump --out <dir>` — best-effort snapshot copy (`cp -R`) while Chrome holds the lock.

Decoding the LevelDB + V8-serialized entries is **not** included — point an external tool
(e.g. Node's `level` + `v8` deserialize) at the dumped copy.

## Caveats

- **macOS-only** (relies on the AppleScript bridge to Chrome).
- **First login is manual.** Never automate the QR auth flow.
- **Detach the extension into its own window.** Popups can't be reached by AppleScript.
- **Selector resilience:** LINE may rotate class hashes between updates; use the fix path above.
- **Path 2 LevelDB lock:** Chrome holds the lock while running; `cache-dump` is a best-effort
  snapshot — quit Chrome first for a clean read.
- Unofficial tool, not affiliated with or endorsed by LINE.
